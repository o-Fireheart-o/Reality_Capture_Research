01 심층

COLMAP

질문 1 심층. 01장이 “SfM/MVS의 기준 구현”이라고 한 줄로 소개한 오픈소스 도구는 무엇이고, 어디까지 쓸 수 있는가

COLMAP은 사진 묶음에서 카메라 위치와 3차원 모델을 복원하는 무료 오픈소스 파이프라인입니다. 현장 납품물을 뽑는 상용 도구라기보다 다른 도구와 연구가 기대는 바닥에 가깝습니다. 3DGS와 NeRF 연구 코드는 대부분 COLMAP 결과를 입력으로 받고, 새 복원 기법은 COLMAP과 비교한 수치부터 내놓습니다.

칩 읽는 법. 오픈소스라 “벤더”가 회사는 아닙니다. 여기서 벤더는 COLMAP 개발진이 자기 도구를 스스로 설명한 문서와 릴리스 노트를 뜻합니다.

사진에서 점군까지 일곱 단계

앞의 세 단계(SfM)가 카메라 위치와 희소 점군을 만들고, 뒤의 네 단계(MVS)가 그 결과로 조밀 점군과 메시를 만듭니다.

①

특징 추출

사진마다 특징점을 찾는다. 기본은 SIFT이고, 4.0부터 ALIKED, 4.2부터 LoMa 같은 학습 기반 특징을 ONNX로 쓸 수 있다.

②

매칭 · 기하 검증

어떤 사진 쌍을 비교할지 고른다. 처리 시간이 여기서 갈린다. 4.0부터 LightGlue 매칭을 지원한다.

③

매퍼 (SfM)

카메라 자세와 3D 점을 푼다. 증분·전역·계층 세 방식 가운데 고른다. 결과는 축척과 위치가 임의인 희소 모델이다.

④

왜곡 보정

렌즈 왜곡을 걷어 낸 사진을 만든다.

⑤

PatchMatch 스테레오

사진마다 깊이 맵과 법선 맵을 계산한다. CUDA GPU가 필요하다. 4.2부터 AMD GPU용 ROCm/HIP 빌드도 된다.

⑥

융합

깊이·법선 맵을 합쳐 조밀 점군 fused.ply를 만든다.

⑦

메시화

포아송 또는 들로네 방식으로 표면을 만든다. 4.0에서 메시 단순화와 텍스처 매핑이 들어왔다.

처음엔 한 줄로 끝까지: colmap automatic_reconstructor --workspace_path ./project --image_path ./project/images

4.x에서 달라진 것

4.0 · 2026-03

전역 매퍼가 본체로

별도 프로젝트였던 GLOMAP(ECCV 2024)이 global_mapper로 들어왔고 GLOMAP 저장소는 폐기됐습니다. 개발진은 증분 방식보다 보통 10~100배 빠르고 품질은 같거나 낫다고 밝힙니다 벤더. 카메라 내부 변수 추정 방식이 달라 결과 파라미터가 달라질 수 있습니다.

4.1 · 2026-06

360 파노라마를 그대로

구면(등장방형) 카메라 모델이 추가돼 360 사진을 잘라 넣지 않고 복원할 수 있습니다. 릴리스 노트는 원근 사진으로 잘라 넣는 기존 방식보다 대체로 빠르지만 덜 정확하다고 직접 적습니다 벤더. GPU 번들조정 Caspar도 이때 들어왔습니다.

4.2 · 2026-09

규모와 하드웨어 폭

전역 매퍼가 끊어진 덩어리를 따로 복원하고, 계층 매퍼를 GUI와 Python에서 고를 수 있게 됐습니다. AMD GPU 조밀 복원, 학습 기반 LoMa 특징, 로컬 웹 3D 뷰어가 추가됐습니다 벤더.

결과를 넘길 때 틀리는 두 지점

희소 모델은 cameras(내부 변수), images(사진별 자세와 2D 특징점), points3D(3D 점과 그 점이 보인 사진 목록) 세 파일이 핵심이고, 바이너리와 텍스트 두 형식이 있습니다.

  • 저장된 자세는 월드→카메라 변환입니다. 카메라 중심은 −Rᵀ·t로 따로 계산해야 합니다. 카메라 축은 X 오른쪽, Y 아래, Z 앞입니다 벤더. Y가 위를 향하는 뷰어로 넘기면 축을 뒤집어야 합니다 추정.
  • 단위가 미터가 아닙니다. 사진만으로는 실제 크기와 위치를 알 수 없습니다. model_aligner로 GPS나 기준점 좌표에 맞추는데, 좌표를 아는 사진이 최소 3장 있어야 상사변환을 추정합니다 벤더. 국가 좌표계와 수직 기준면 처리, 정확도 검증은 사용자 몫입니다 추정.

누가 COLMAP 위에 서 있나

3DGS 원 구현은 자기 장면을 학습시키려면 COLMAP을 설치하고 convert.py를 돌리라고 안내합니다. 입력 폴더도 COLMAP의 sparse/0/ 구조 그대로입니다. nerfstudio도 사진·영상 처리에 COLMAP을 쓰되, 휴대폰 LiDAR나 SLAM으로 자세를 이미 구한 데이터와 Metashape·RealityCapture·ODM이 내보낸 카메라 값은 COLMAP 없이 받습니다.

그래서 COLMAP 포맷은 신경 렌더링 쪽의 사실상 교환 포맷이 됐습니다 추정. 상용 도구가 COLMAP 형식으로 내보낼 수 있는지가 3DGS 연계 가능성을 가릅니다.

DUSt3R·VGGT 같은 순전파 모델은 사진이 10장 미만일 때 COLMAP보다 완전성이 최대 50% 좋았지만, 사진이 많아질수록 자세 신뢰도가 떨어졌습니다. 대체재보다 보완재입니다. COLMAP 쪽도 ALIKED·LightGlue 같은 학습 기반 부품을 흡수하고 있습니다.

쓰기 전에 알아 둘 한계

  • GPU. 조밀 복원은 CUDA 또는 ROCm/HIP GPU가 있어야 합니다. 리눅스 배포판 기본 패키지에는 GPU 지원이 빠져 있어 직접 빌드해야 하고, GPU용 Python 휠은 현재 리눅스용만 있습니다 벤더.
  • 촬영 조건. 질감 없는 면(흰 벽)을 피하고, 모든 물체가 최소 3장에 보이게 하고, 조명을 고르게 하고 반사를 피하고, 제자리에서 돌지 말고 옮겨 가며 찍으라고 문서가 직접 권합니다 벤더. 흰 벽·유리·반복 패턴이 많은 건설 실내와는 정면으로 부딪칩니다 추정.
  • 규모. 사진이 수천 장을 넘으면 조밀 복원에서 메모리가 먼저 모자랍니다. 장면 분할, 참조 사진 수 축소, 캐시 조정을 권합니다 벤더.
  • 배포 파일. Windows 바이너리는 코드 서명이 없어 첫 실행 때 보안 경고가 뜰 수 있습니다 벤더. 서명 없는 실행 파일을 막는 회사라면 미리 확인해야 합니다.
  • 라이선스. COLMAP은 BSD지만 함께 빌드하는 의존성의 라이선스가 결과물에 영향을 줄 수 있다고 명시합니다 벤더. 제품에 넣으려면 의존성을 따로 검토해야 합니다 추정.

이 절이 답하지 못한 것
  • COLMAP과 상용 도구의 절대 정확도를 같은 조건에서 비교한 동료검토 연구를 찾지 못했습니다. 건설 현장 비교 연구가 하나 검색됐지만 철회된 논문이라 쓰지 않았습니다.
  • 전역 매퍼와 Caspar의 속도 주장, 360 모델의 정확도 손실은 개발진 자료로만 확인했습니다.
